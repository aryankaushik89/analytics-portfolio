# Walkthrough

## A short explanation

“I wanted to show the part of an AI analytics assistant that is easy to skip: metric definitions, safe query execution and measurable answers. The first version does not call a model. It uses a deterministic parser as a baseline and makes every query inspectable.”

## Interface

### Question box

Enter one of the checked example questions or select an example chip. The static dashboard replays results generated by the Python engine against the project database.

### Run approved metric

Looks for an exact checked example in the browser replay. Questions outside those examples fall into clarification or unsupported handling. The Python engine supports the tested month and year patterns more generally.

### Result card

Shows the answer, the interpreted request and the returned rows. **Export result** downloads the visible table as CSV. The button is disabled when no query ran.

### Approved query

Shows the SQL template and bound parameters. **Copy SQL** copies the displayed query and is disabled for clarification or unsupported results.

### Metric definition

Keeps the meaning beside the result so the answer is not just a number.

### Guardrail notes

Summarize the registry, read-only execution and honest fallback. The “offline checked replay” label is intentional: the hosted static page is not connected to SQLite or an LLM.

## Python flow

1. Normalize the question and identify an approved intent.
2. Extract a month or year into bound parameters.
3. Select a reviewed SQL template from the registry.
4. Validate that it is a single SELECT or WITH query against approved tables.
5. Open SQLite with read-only and immutable flags.
6. Use a SQLite authorizer and progress handler as additional controls.
7. Return at most 200 rows with the SQL, parameters, definition and formatted answer.
8. Compare every supported result with an independent pandas calculation.

## Expected questions

**Why not generate SQL with an LLM?** A live model and supported key were not available for this release. More importantly, the deterministic version is a useful baseline. A later model should beat it on unseen paraphrases without weakening the query controls.

**Is the dashboard querying the database?** No. Python performs the checked SQL work. The static browser page replays those outputs so it can be hosted without a server.

**Why show the SQL?** It makes the metric answer reviewable. An analyst can inspect the table, filters and definition instead of trusting a fluent sentence.

**What stops an injection?** User text never becomes SQL. It selects a registered template. Validation, bound parameters, a read-only connection and the SQLite authorizer add separate checks.
