# Portfolio working conventions

Keep the code and writing readable and specific. Use short analytical steps, imports on separate lines, meaningful names and simple comments. Learning notebooks use numbered sections with the question, code, observed result and interpretation close together. Avoid unnecessary classes, long helpers and broad framework layers.

Each project needs its own business question, data source and licence notes, a reproducible run path, checked outputs, findings, limitations and a walkthrough. Include interface controls and example tasks when there is a dashboard or app. Keep project specific validation inside the project folder.

Label synthetic data and simulated business effects clearly. Do not publish confidential employer or assessment data, credentials, personal career notes or application materials. Distinguish actual integrations from proposed configurations and offline demonstrations from live model runs.

Preserve existing projects. Add new work under its numbered projects folder and update the root index after a successful release. Respect source data licences separately from the code licence. Read a project's own AGENTS.md before editing it.
